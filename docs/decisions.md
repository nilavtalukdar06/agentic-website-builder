# Decisions

Package-first log (see `docs/plan.md` §0.1). One line per decision: feature → package → why → rejected alternatives.

## Phase 0 (recorded retroactively)

- **UI primitives** → shadcn/ui `base-nova` style (Base UI, `@base-ui/react`) → set at bootstrap; AI Elements ships a Base UI build → Radix (`new-york`) not used.
- **Class merging** → `cn` (shadcn's compiled clsx + tailwind-merge) → drop-in, smaller → `clsx` + `tailwind-merge`.

## Phase 1 — design system

- **Theme switching** → own `ThemeProvider` (`src/components/theme/`) → `next-themes` 0.4.6 (last release March 2025) fails the "maintained in the last ~6 months" check and renders a `<script>` inside a client component, which React 19.3 reports as an error; ours is ~100 lines with `useSyncExternalStore`, an inline `<script>` in the root layout's `<head>` for the first paint (see "Theme init script" under Phase 5) and a `theme-light` root class so `.light` stays free for scoped panels → `next-themes`.
- **URL state** → `nuqs` v2 → plan default; shared parsers in `src/lib/search-params/` → —
- **Icons** → `lucide-react` → plan default; lucide 1.x has no brand marks, so the GitHub mark is a small own SVG (`src/components/icons/github-icon.tsx`) → `react-icons/si` (whole-set dependency for one icon).
- **Toasts** → shadcn `toast` (Base UI Toast) → the shadcn skill prescribes `toast` for Base UI projects; `sonner` is the Radix/Aria choice → `sonner` (the plan named it before the Base UI base was chosen).
- **File-type icons** → `@iconify-json/material-icon-theme` (MIT, dev dependency) + `@iconify/utils`, subset generated by `scripts/generate-file-icons.mjs` into `src/components/files/file-icons.generated.ts` (~7 KB) → matches the canvas (React atom, blue TS square, purple CSS, yellow JSON braces) with no runtime fetch and no 3 MB JSON in the bundle → `@iconify-json/vscode-icons` (renders TSX/JSX as text, doesn't match the canvas), `@iconify/react` online mode (runtime API fetch), hand-drawn SVG map.
- **Code highlighting** → AI Elements `code-block` (Shiki) → plan default. Themes switched to `github-light-default` / `github-dark-default` to match the `--code-*` tokens and pass AA (legacy `github-light` keyword color is below 4.5:1). The `pre` background is transparent so code sits on our surfaces → `shiki` directly.
- **Markdown in chat** → `streamdown` (pulled in by AI Elements) with only the `code` plugin → math (KaTeX), mermaid and CJK plugins removed: heavy and not needed for a coding agent's replies → full plugin set.
- **AI Elements extra deps** → `ai` (types only: `UIMessage`, `ToolUIPart`…), `motion` (Shimmer), `use-stick-to-bottom` (Conversation), `ansi-to-react` (Terminal), `cmdk` (Command), `@radix-ui/react-use-controllable-state` (Reasoning; a tiny state hook, no Radix primitives) → accepted as AI Elements dependencies → —
- **Resizable panes** → shadcn `resizable` (`react-resizable-panels` v4) → plan default → —
- **Contrast testing** → `@axe-core/playwright` (dev only) → the plan requires "axe shows no contrast errors". License is **MPL-2.0**, outside the MIT/Apache/ISC list; accepted as a test-only exception because it is never shipped and every axe package carries the same license → manual contrast checks only.

## AI Elements patches for Base UI

AI Elements was installed from its registry and then adapted. Re-apply these if the components are re-added:

- `prompt-input.tsx`: `DropdownMenuItem` `onSelect` → `onClick`; hover-card delays moved from root to trigger (`delay` / `closeDelay`); `TooltipTrigger` uses `render`.
- `message.tsx`: `TooltipTrigger` uses `render` (it was nesting `<button>` in `<button>`).
- `task.tsx`, `tool.tsx`, `reasoning.tsx`, `web-preview.tsx`: Radix `data-[state=open|closed]` selectors → Base UI `data-panel-open` / `data-open` / `data-closed`.
- `tool.tsx`, `terminal.tsx`, `file-tree.tsx`, `web-preview.tsx`: raw palette colors (`text-green-600`, `bg-zinc-950`…) → tokens (`text-success`, `bg-card`…).
- `code-block.tsx`: render-time ref mutation replaced with keyed state; the synchronous highlight cache is read only after hydration (fixes a hydration mismatch); transparent background; line numbers use `--code-ln`.
- `shimmer.tsx`: `motion.create()` during render replaced with a static `p` / `span` / `div` map.
- `file-tree.tsx`: `aria-selected` / `aria-expanded` on tree items; sans font, matching the Code artboard.
- `prompt-input.tsx`: the `InputGroup` root gets `has-disabled:opacity-100 has-disabled:bg-transparent dark:has-disabled:bg-input/30`. shadcn's group fades to 50% (and tints) when **any** descendant is disabled, so one disabled control (the mic in Firefox, the paperclip at 4 images, the model chip while it loads) washed out the whole composer; measured 0.5 opacity in Chromium with the mic disabled. Disabled buttons still dim themselves. Covered by an e2e test, since jsdom doesn't evaluate the CSS.
- `prompt-input.tsx`: added `PromptInputSpeechButton` (Web Speech API, see Phase 5) and `PromptInputAttachment` / `PromptInputAttachments` (ported earlier); the registry's speech button was rewritten because it assigns `textarea.value`, which controlled textareas ignore.

## Phase 2 — database, tRPC, env

- **Env validation** → `@t3-oss/env-core` + `zod` in `src/config/env.ts` → typed, fails `dev`/`build` fast (imported from `next.config.ts`), client/server split enforced at runtime; `env-core` (not `env-nextjs`) was the owner's choice, so `runtimeEnv` lists every var explicitly → `@t3-oss/env-nextjs`.
- **ORM** → Prisma **7.10.1**, all Prisma packages pinned → the owner requires v7; `prisma@latest` on npm is now an 8.0 RC, so never install unpinned → Prisma 8, Drizzle.
- **Prisma client** → `prisma-client` generator to `src/generated/prisma` (git-ignored, regenerated by `bun run build` / `bun run db:generate`; no `postinstall`, because `prisma.config.ts` needs `DIRECT_URL` and installs run before env is set) → `@prisma/client` in `node_modules`.
- **Neon driver** → `@prisma/adapter-neon` + `@neondatabase/serverless` → plan default; no `ws` dependency because Node ≥ 22 has a global `WebSocket` (add `ws` only if a runtime lacks it) → `@prisma/adapter-pg` + `pg`.
- **Migrations URL** → `prisma.config.ts` reads `DIRECT_URL` through Prisma's own `env()`, not `src/config/env.ts`, so `migrate deploy` never depends on unrelated app vars.
- **tRPC** → v11 + `@trpc/tanstack-react-query`, `superjson` → plan default. Server prefetch uses `getQueryClient().prefetchQuery(...)` directly (a generic `prefetch` helper failed to type-check against tRPC query options).
- **Dev proof page** → `/dev/trpc` (list + `[slug]`) with skeleton, error, empty and not-found states → proves seed → server fetch → hydrate → client refetch before auth exists; served only when `NODE_ENV !== "production"` or `DEV_ROUTES_ENABLED=true` (Playwright runs a production build, so a pure `NODE_ENV` gate would make the e2e spec impossible). Removed in Phase 4 (with `DEV_ROUTES_ENABLED`) once the real pages and `e2e/projects.spec.ts` covered the same path.
- **Better Auth tables** → hand-written `User`, `Session`, `Account`, `Verification` (table names `user`, `session`, `account`, `verification`) so `Project.userId` has a real FK; Phase 3 re-checks them against `@better-auth/cli generate`.
- **E2E needs data** → specs that use the signed-in fixture are skipped when `DATABASE_URL` is unset.

## Phase 3 — authentication

- **Auth** → `better-auth` 1.7 with the Prisma adapter, GitHub as the only provider → plan default; its Prisma peer range covers v7. The hand-written `user` / `session` / `account` / `verification` models were diffed against `@better-auth/cli generate` output and match, so no extra migration → Auth.js, Clerk.
- **Scopes** → `read:user user:email` with `disableDefaultScope`; repo access is requested at first export with `linkSocial` (Phase 8) → matches the sign-in copy on the canvas → `repo` at sign-in.
- **OAuth tokens** → `account.encryptOAuthTokens: true` → the GitHub access token is later used server-side for export, so it is encrypted at rest.
- **Session lookups** → `session.cookieCache` (5 min, compact) → fewer DB reads per request; revocation can take up to 5 minutes to apply.
- **Route protection** → `src/proxy.ts` checks only for the session cookie (`getSessionCookie`) on `/`, `/projects`, `/usage`, `/p/*` and redirects to `/sign-in?callbackURL=…`; `requireSession()` and `protectedProcedure` stay authoritative. The proxy does **not** bounce signed-in users away from `/sign-in`: a stale cookie would loop between `/` and `/sign-in`. The sign-in page does that redirect after a real `getSession()`.
- **Open redirects** → `callbackURL` is a nuqs parser (`src/lib/search-params/sign-in.ts`) that only accepts same-origin relative paths; Better Auth also validates it against trusted origins.
- **Welcome credits** → `WELCOME_CREDITS` env var, default 0; a `databaseHooks.user.create.after` writes one `CreditLedger` row (`ADJUSTMENT`, `meta.kind = "welcome"`) only when it is > 0.
- **Spinner inside buttons** → `aria-hidden` on the `Spinner` (it carries `role="status"` + `aria-label="Loading"`), because the button label already says what is happening.
- **Gap (needs pages)** → Terms, Privacy, Docs, Status and Contact links on the sign-in screen are `#` placeholders until those pages exist.
- **E2E signed-in fixture** → `e2e/fixtures/session.ts` inserts a user + session with `@neondatabase/serverless` and sets the HMAC-signed `better-auth.session_token` cookie (same signing as `better-call`); the user row is deleted afterwards.

## Phase 4 — app shell, Home, Projects

- **Slug generation** → `@sindresorhus/slugify` 4 (MIT, ESM, typed, released Nov 2026) → transliterates (`&` → `and`, `é` → `e`) so names like "Ember & Oak" give readable slugs; uniqueness comes from the DB: insert, and on a `P2002` on `slug` retry with a 4-character `nanoid` suffix (max 5 tries) → `slugify` (last release ~7 months ago, outside the maintenance window), hand-rolled regex.
- **Project name from the prompt** → own helper (`src/lib/project-name.ts`): first sentence, leading "build me a / an / the…" removed, capped at 48 characters on a word boundary → no package does this; Phase 5 may let the agent rename the project.
- **Relative time** → `Intl.RelativeTimeFormat` with `numeric: "auto"` (`src/lib/relative-time.ts`) → no dependency and gives the canvas copy as-is ("yesterday", "last week", "2 hours ago") → `date-fns` `formatDistanceToNow` ("1 day ago", "7 days ago").
- **⌘K** → shadcn `Command` (`cmdk`, already installed in Phase 1) in `CommandDialog` → plan default → —
- **Projects search** → server-side `contains` / `mode: "insensitive"` on name, slug and description; the URL update uses nuqs `debounce(300)` and the query key a 10-line `useDebouncedValue` (nuqs returns the new state immediately), with `placeholderData: keepPreviousData` so the grid doesn't flash → full-text search (not needed at this size).
- **Limits shared by server and client** → `src/lib/project-limits.ts` (plain module) → a constant exported from a `"use client"` file reaches a Server Component as a client reference, not its value: the layout's prefetch sent `{ limit: <function> }`, failed validation silently (`prefetchQuery` swallows errors) and the page fell back to a client fetch. `e2e/projects.spec.ts` now asserts the server HTML contains the user's projects.
- **Command palette** → this shadcn `CommandDialog` renders `children` straight into `DialogContent`, so callers wrap them in `<Command>` (cmdk crashes with "reading 'subscribe'" otherwise).
- **Not-found status on `/p/[slug]`** → with a `loading.tsx` the response streams, so `notFound()` returns 200 with a `noindex` robots tag rather than a 404 status (documented Next.js behavior); kept, because the skeleton is mandatory.

## Phase 3.1 — public pages

- **Uptime data** → own `HealthCheck` table + `/api/cron/health` probe + Vercel Cron every 5 minutes → no external service needed and the numbers are the app's own; a pure bucketing function (`src/lib/status.ts`) is unit-tested → hosted monitors (Better Stack, UptimeRobot, Instatus: another account and a paid tier for a public status page), faking data (a status page must not).
- **Probe semantics** → the probe runs inside the app and checks the database, so a full outage writes nothing; past hours therefore count missing checks as down, and hours before the first check are "No data". Vercel Hobby limits cron to once a day: the 5-minute schedule needs Pro, or point any external pinger at the same route with the bearer token.
- **Status bars** → plain flex divs coloured with `--success` / `--warning` / `--destructive` / `--muted` + shadcn `Tooltip` → a chart library for 24–168 equal-width bars is overkill and Recharts is reserved for the usage page.
- **Brand marks** → own SVGs for Instagram and LinkedIn (`src/components/icons/`), stroke style like lucide → lucide 1.x has no brand icons, `react-icons` / `simple-icons` would pull in whole sets for two glyphs.
- **Docs content** → typed TS data rendered by one `DocBlocks` component → MDX (`@next/mdx` plus loaders) for six short articles, and a CMS.
- **Legal copy** → drafted from what the app actually stores (Better Auth tables, credit ledger, payments, sandbox providers in the plan); governing law is India because the plan targets Indian billing. Needs the owner's review, it is not legal advice.

## Phase 5 — sandbox + coding agent

- **Durable functions** → `inngest` **v4** (4.26) → plan default, latest major; v4 types events with `eventType()`, puts triggers in the function options and ships realtime in core → v3 (still what AgentKit and `@inngest/realtime` were built against).
- **Agent loop** → Vercel **AI SDK** (`ai` v7, already installed for AI Elements types), models through AI Gateway (below), with our own loop in `run-agent`: every model turn and every tool call is its own `step.run`, so retries resume mid-run and each step shows in the Inngest dev server. Tools are declared with `tool({ inputSchema })` and **no `execute`**, so the SDK returns tool calls instead of running them → `@inngest/agent-kit` 0.13.2 (owner's call at Phase 5 start): last stable release Nov 2025 (outside the 6-month rule), built against inngest 3.43, and its OpenAI adapter only speaks Chat Completions, while the AI SDK reaches every provider and reports cached/reasoning token usage.
- **Agent → UI streaming** → Inngest v4 core realtime: `realtime.channel()` (zod topic schemas) + `inngest.realtime.publish()` inside steps, `getClientSubscriptionToken` + `useRealtime` from `inngest/react` for Phase 6 → `@inngest/realtime` 0.4 (depends on inngest v3) and `@inngest/use-agent` 0.4 (last release Oct 2025, AgentKit event set).
- **Publishing** → non-durable `inngest.realtime.publish` called only inside `step.run` callbacks, wrapped so a realtime failure never fails a step → `step.realtime.publish` (one durable step per event: hundreds of steps per run for streamed deltas).
- **Realtime topic names** → single words (`status`, `reasoning`, `text`, `task`, `file`, `tool`, `credits`, `preview`) with a `phase` field where the plan had two events (`file.started` / `file.written`); `text` added for streamed assistant text. Mapping table in `docs/plan.md` §5.3.
- **Token endpoint** → `POST /api/realtime/token` route handler, as the plan's layout lists → tRPC procedure (would also work; kept the plan's file so `useRealtime`'s token factory has a plain URL).
- **Sandbox** → `e2b` 2.63 with the **Template SDK** (`sandbox-templates/nextjs/template.ts`, built by `bun run sandbox:build`) → `@e2b/cli` + Dockerfile (the SDK builds remotely, no Docker or CLI install needed). The template's `shadcn create` and `add --all` steps were checked locally (see the `shadcn create` entry below): the app type-checks and serves 200.
- **Template shadcn style** → `base-nova` on Base UI (`--base base --preset nova`, the same style and Geist font as Vibe's own `b2fA` preset); the system prompt tells the agent to use `render` instead of `asChild` → pinning a Radix style (would differ from Vibe's own components).
- **Sandbox restore** → done in Phase 5 rather than Phase 9: when the stored sandbox is gone, a new one is created and the latest Version's files are written back (plus `npm install` when `package.json` is restored). Without it, every follow-up after the 30-minute timeout would start from an empty template.
- **Version snapshot** → the whole source tree read from the sandbox at the end of a run (not only the files the agent wrote), because Phase 6's Code view and Phase 8's export both read `Version.files`. Lock files, `.env*`, binaries, `node_modules`, `.next`, `.git` are left out; capped at 400 files / 4 MB.
- **Idempotency** → ids derived from the Inngest run id (`run_<runId>_reply|version|debit`) plus `upsert` / existence checks → a new `runId` column (needs a migration and buys nothing over deterministic ids).
- **Metering** → cost-based (owner's call): `ceil(USD cost × CREDITS_PER_USD × CREDIT_MARKUP)`, USD cost from AI Gateway (below). Failed runs are free (owner's call). Pure functions in `src/server/billing/pricing.ts` and `run-cost.ts` → flat per 1K tokens, flat per run, hand-maintained prices in env (the first Phase 5 draft; replaced at the owner's request).
- **Out of credits** → checked before the run (balance ≤ 0: no model call, assistant explains) and after every turn (running cost ≥ balance: stop, keep and charge what was built; the balance can end slightly below 0) → hard stop mid-turn (would lose paid work).
- **Command guard** → small regex denylist (`src/server/sandbox/guards.ts`, unit-tested): `sudo`, dev-server start/stop/build, `kill`, recursive deletes of `/` `~` `.` `*`, `curl | sh`, `.env` → an allowlist (too narrow for a coding agent that needs `npx`, `ls`, `cat`, `tsc`…).
- **Required env** → `AI_GATEWAY_API_KEY`, `E2B_*` and the Neon storage `AWS_*` vars are required in `src/config/env.ts` (dev/build fail fast without them), Inngest keys optional (the SDK runs against the Dev Server with `INNGEST_DEV=1`).
- **Smoke test** → `scripts/agent-smoke.ts` (`bun run agent:smoke`), run with `bun --conditions=react-server` so `server-only` modules import outside Next.js → a Vitest integration test (would need real keys and spend credits on every test run).
- **Model provider** → **Vercel AI Gateway** through the AI SDK (`createGateway` from `ai`; `@ai-sdk/gateway` ships with `ai`) (owner's call: "use AI Gateway, don't stick to OpenAI") → `@ai-sdk/openai` direct (removed): no model catalogue, no pricing, no cost lookup, one provider. The gateway also allows BYOK if the owner wants to bill a provider key directly.
- **Model list** → a **curated allowlist** of agentic-coding models across 8 providers (`src/lib/ai/models.ts`, each with a hand-checked `vision` flag), intersected at runtime with `gateway.getAvailableModels()` (cached 1 h) for names and live prices → showing the whole catalogue (500+ models, many without tool use or too weak for a coding loop; the SDK entry has no capability tags to filter on) or the public `/v1/models` endpoint (has tags, but isn't the SDK method the owner asked for). Default `anthropic/claude-sonnet-5.5` via `AI_DEFAULT_MODEL`.
- **Run cost** → **exact** cost per call from `gateway.getGenerationInfo({ id })` (`totalCost`, or `upstreamInferenceCost` for BYOK) using the `generationId` captured with `onLanguageModelCallEnd`, looked up once in a `cost` step at the end of the run (3 tries, 0 / 2 / 5 s, since the record can lag); any call without a result is billed at the live-price estimate. During the run only the estimate is used (live `credits.used`, out-of-credits stop) → estimate only (drifts from the real bill), lookup after every turn (adds latency to every step).
- **Model picker UI** → AI Elements **`model-selector`** (searchable command dialog), adapted to Base UI and our `Command` / `Dialog`; the registry's `ModelSelectorLogo` (an `<img>` from models.dev) is left out → a `Select` (no search) or an own popover. Grouped by provider with price per 1M tokens and an image icon for vision; non-vision models are disabled while images are attached. Loading = skeleton chip, error = "Models unavailable" chip that retries, empty = `CommandEmpty`.
- **Attachment storage** → **Neon Object Storage** (owner's call), private bucket `attachments` declared in `neon.ts` (`@neon/config`, dev dependency), accessed with **`files-sdk`** + its `neon` adapter (MIT, the Neon skill's recommended client; AWS SDK v3 packages as peers) → Vercel Blob, Postgres `bytea`, raw `@aws-sdk/client-s3`. Objects are keyed `users/<userId>/<nanoid>.<ext>`; Postgres stores the key, never the bytes.
- **Upload path** → `POST /api/attachments` route handler (multipart) instead of tRPC, because tRPC's JSON batching doesn't carry files; 4 MB cap per image keeps uploads under Vercel's 4.5 MB request-body limit → presigned browser uploads (would need CORS on the bucket, which Neon's S3 compatibility doesn't document). The client helper lives in `src/lib/upload-attachment.ts`, not in a component.
- **Images to the model** → bucket keys in history as `vibe-attachment:` placeholders, swapped for 1-hour presigned URLs inside each model step (the gateway accepts image URLs) → bytes in messages (would land in Inngest step state, 4 MB step limit) or long-lived public URLs.
- **Attachment chips** → `PromptInputAttachment` / `PromptInputAttachments` ported from the AI Elements registry into our `prompt-input.tsx` (they were missing from the installed copy): `HoverCardTrigger` uses `render`, previews use `next/image` with `unoptimized` (blob/data URLs).
- **Database** → migration `agent_models_and_attachments`: `Message.model` and an `Attachment` table (owner, optional message, unique key, name, type, size), additive only.
- **Runaway output** → `maxOutputTokens: 32_000` per turn, and a turn that ends with `finishReason: "length"` is dropped from history with a note to take smaller steps → no cap (found in the live test: a model generated 128 k tokens of garbage in one turn, and the next turn overflowed its context window).
- **Context size** → `compactHistory()` before every model step: turns older than the last 3 keep their structure, but file contents in old `createOrUpdateFiles` calls become "[N lines written earlier]" and old tool output is cut to 1,500 characters; `readFiles` returns at most 20 k characters per file and 60 k per call → summarising with an extra model call (cost and latency).
- **Model errors** → `classifyModelError()` walks the error, its `cause` and the AI SDK's `lastError`: 429 → Inngest `RetryAfterError` with the gateway's wait (AI Gateway's free tier allows 5 requests per minute per model); 401/403/404 → `NonRetriableError` with a "pick another model" reply (free tier blocks most models); 400/413/422 → `NonRetriableError`; other errors → normal retries → retrying everything (wasted runs and time on errors that can't succeed).
- **Free-tier testing** → only `openai/gpt-5.1-codex-mini`, `moonshotai/kimi-k2.7-code` and `alibaba/qwen3-coder-next` of the curated list were open on the owner's free AI Gateway credits (probed Nov 2026); the local `AI_DEFAULT_MODEL` is set to `openai/gpt-5.1-codex-mini`. With paid credits every curated model works, so the curated list is unchanged.
- **Inngest Dev Server script** → `npm exec --ignore-scripts=false -- inngest-cli@latest dev` → `npx …`, which `bun run` rewrites to `bun x`; Bun skips install scripts, so the CLI binary never downloads.
- **Persist transaction** → `$transaction(fn, { maxWait: 15_000, timeout: 30_000 })` → Prisma's defaults (2 s to start, 5 s to run): over the Neon WebSocket adapter a cold connection took longer than 2 s to open the transaction in the live test, and the snapshot write (up to 4 MB of JSON) needs headroom.
- **Template scaffold** → **`shadcn create`** (alias of `shadcn init`; owner's call): `npx shadcn@latest create --name app --template next --base base --preset nova --no-monorepo --yes` run from `/home/user`, then `add --all` → `create-next-app@16` followed by `shadcn init --defaults`. It is one command, runs without prompts, and yields a project that is shadcn-native from the first file (`components.json`, `ThemeProvider`, Geist via `next/font`, `hooks/`, `lib/utils.ts`). Checked in a scratch directory: same layout as before (no `src/`), 63 components after `add --all`, `tsc` clean, dev server 200. Differences the agent must know about, now in the system prompt: the layout has **no `metadata` export** (the old template had "Create Next App"), `app/page.tsx` is a "Project ready!" placeholder, and the layout wraps the app in a `ThemeProvider` (next-themes, `defaultTheme="system"`).
- **Dark mode in generated sites** → the template's `ThemeProvider` follows the visitor's system setting, so an agent that hard-codes a light palette would clash with shadcn components for visitors in dark mode. The prompt tells the agent to style with theme tokens, or to pass `forcedTheme="light"` / `"dark"` for a fixed palette → removing `ThemeProvider` from the template (shadcn's own pattern, and sites get dark mode for free) or leaving the agent to find out.
- **Composer chips** → the **Public** (visibility) and **Next.js** (framework) chips are removed from the prompt input (owner's call; they were disabled placeholders). This departs from the `vibe-ui` Home screenshot on purpose. Visibility returns with Phase 8 if export needs it; a framework chip returns when a second template exists.
- **Dark-mode check in the live test** → the agent run on the `shadcn create` template (gpt-5.1-codex-mini) used theme tokens almost everywhere (48 token classes, no raw palette classes, metadata set, placeholder replaced) but put `text-foreground` on a hard-coded light gradient in one section, which would be unreadable in dark mode. The prompt now names that exact mistake (fixed backgrounds need fixed text colors). Not re-run live: free-tier rate limits make a run take 15+ minutes; worth re-checking with the first paid-credit run.
- **Preview hot reload (`allowedDevOrigins`)** → the template's `next.config.ts` sets `allowedDevOrigins: ["*.e2b.app"]` (one label wildcard, matching `3000-<id>.e2b.app`) → nothing (reported from the browser console: `WebSocket connection to 'wss://3000-<id>.e2b.app/_next/hmr' failed`). Next 16 blocks dev-only endpoints for any host except `localhost` and its own hostname, so the preview rendered but the HMR socket was refused. Reproduced on real sandboxes: with the sandbox host as `Origin` the dev server dropped the socket every time (five tries over 20 s, page warm), `localhost` as `Origin` got 101, and writing the setting made the public `wss` URL return 101 within 4 s (Next restarts itself when `next.config.ts` changes). It matters most for Phase 6, where the preview iframe should update as the agent writes files.
- **Keeping it (`ensureDevOrigins`)** → a deterministic guard instead of relying on the prompt: before the agent starts and before the snapshot, `ensureDevOrigins()` reads `next.config.ts` and, when the option is missing, inserts it (`withDevOrigins`, a pure function: empty config, config with options, already set, unrecognised shape = no-op). Needed because the setting can be lost in two ways: a restore writes an older Version's `next.config.ts` over the template's (projects created before this fix), and an agent may rewrite the file without it (the live tests showed agents miss prompt rules). The prompt also says to keep it. The template step uses `sed` + `grep -q` in the container (GNU `sed` understands `\n`), because a template build can only run shell commands, not TypeScript; both places share the origin constant (`ALLOWED_DEV_ORIGIN` in `src/server/sandbox/dev-origins.ts`) → relying on the prompt alone, or on the template alone.
- **Model logos** → marks from **`@lobehub/icons-static-svg`** 1.102 (MIT, dev dependency), a generated subset in `src/components/models/model-logos.generated.ts` (~13 KB) rendered inline, same pattern as the file icons (`scripts/generate-model-logos.mjs`, `bun run logos:generate`). **Colored** where the set has a colored mark (owner's call): Claude (Anthropic models), **Codex** (any model id containing `codex`, so GPT-5.x Codex models do not show the OpenAI blossom), Gemini (Google), Kimi (Moonshot), DeepSeek, Alibaba, Mistral. OpenAI (non-Codex models) and Z.ai only exist as single-color marks, so they use `currentColor` and follow the theme (Z.ai has no colored mark in the set; the Zhipu one is the company's older brand) → AI Elements' `ModelSelectorLogo` (`<img src="https://models.dev/logos/…">`: every user's browser would call a third party on each open, and it needs `next/image` or an `<img>` lint exception), `@iconify-json/lobe-icons` (doesn't exist on npm). The logo is chosen per **model id** (`modelLogoKey`), not per provider, which is what lets Codex models differ from the rest of OpenAI. Gemini and Codex use SVG gradients with fixed ids, so `ModelLogo` rewrites each id with `useId()` per instance (identical ids repeated in one page break gradients if the first copy is hidden, and are invalid HTML). The generator rejects scripts, styles, images, `<use>`, `href` and event handlers (the markup goes through `dangerouslySetInnerHTML`) and any `url(#id)` that has no matching id; a unit test requires every curated model to have a logo. On a dark menu all the colored marks stay visible (checked in screenshots of both themes); in light theme the Codex mark's white tile blends into the menu, so only its blue glyph shows. The marks are trademarks of their owners and are used only to identify which model is selected.
- **Voice input** → the browser **Web Speech API** behind `PromptInputSpeechButton` (the AI Elements registry's pattern, rewritten): `SpeechRecognition` with `continuous` and `interimResults`, language from `navigator.language`, `@types/dom-speech-recognition` 0.0.12 (MIT, types only; TypeScript 5.9 has none) → server transcription through AI Gateway (every browser, but per-minute cost, recording and upload code, size limits and credit metering for a feature on a free-tier gateway), a paid speech SDK. Cost: nothing. Limits: Firefox has no `SpeechRecognition`, and Chrome/Edge send audio to the vendor's service (stated in the privacy policy).
- **How dictation writes** → through `PromptInputProvider`'s `setInput` as `base + all words so far` (the engine re-sends the whole session, so interim text is replaced, not duplicated) → the registry's version, which sets `textarea.value` and dispatches an `input` event: a React-controlled textarea ignores that. The "edit" check compares the input with what dictation last wrote: a difference means the user typed, so it **aborts** (`abort()` drops pending results; `stop()` would still deliver them and overwrite the edit). Submitting disables the button, which also aborts, so late words can't land in the cleared box. Clicking the mic again uses `stop()` so the last words are kept.
- **Support detection** → `useSyncExternalStore` with a server snapshot of "unsupported" (no hydration mismatch, no setState in an effect) → `useEffect` + `useState`, which the React Compiler lint rules flag.
- **Model picker layout** → the dialog is `sm:max-w-lg` (was `max-w-sm`), rows are logo, flexible name, a fixed 16 px slot for the "reads images" icon, and a right-aligned price column on `sm` and up (the price never shrinks, the name truncates last) → leaving the 384 px default: with the logo added, names truncated to "Claude Haik…" and could not be told apart (Haiku 5.5 vs 4.5), found by looking at screenshots in both themes.
- **Speech button review (owner asked to fix the two files; VS Code showed no problems and ESLint, `tsc` and Prettier were clean, so these are defects found by reading and testing)** → (1) unsupported browsers: the Button styles disabled as `disabled:pointer-events-none`, so a natively disabled mic never receives hover and the "isn't supported in this browser" tooltip could not appear; the button now uses `aria-disabled` via Base UI `focusableWhenDisabled` (hoverable, focusable, click does nothing) with `data-disabled:` styles, and keeps a real `disabled` only while a prompt is being sent. (2) race: with the browser's permission prompt open `listening` is still false, so a second click created a second recognizer and the first one's late `end` event flipped the UI to "not listening" while recording; every handler now checks it belongs to the current recognizer, `start()` aborts the previous one, and unmount clears the ref before aborting. (3) the label stays "Dictate" with `aria-pressed` (a toggle button must not change its name as well as its state; only the tooltip text changes). (4) `onSpeechError` is read from a ref so a re-rendered parent's newer callback is used. (5) `speechErrorMessage` used `in` on a plain object, so a code such as `constructor` returned a function; it uses `Object.hasOwn`. Headless Chromium has no speech backend (no events at all), so real recognition can only be checked in a real Chrome.
- **Theme init script** → a plain inline `<script dangerouslySetInnerHTML>` in `<head>` of the root layout (a Server Component, so React doesn't warn about it), replacing `<Script strategy="beforeInteractive">` → keeping `next/script`. In Next 16's App Router that strategy is delivered as `(self.__next_s=…).push(…)`, a queue Next's runtime runs during bootstrap, and the docs say it runs "before any Next.js code and before hydration" and "does not block page hydration": it is not meant to run before first paint. The server HTML has no theme class, so every dark-theme load (the default) painted the light theme first, then switched, and `transition-colors` on cards and buttons faded between them. Measured with a `transitionrun` listener installed at document start: 30 transitions on a dark load in Chromium, Firefox and WebKit, 0 on light. It was found because axe's contrast check intermittently failed in Firefox in full-suite runs (`/design`, `/sign-in`, `/contact`), reporting a card background of `#5f5f5f` that is in neither theme, i.e. a mid-fade color; the failures were never in the components under test. After the change: 0 transitions in both themes in all three browsers, no console or hydration errors. `e2e/theme.spec.ts` guards it (zero transitions on load for `/sign-in`, `/contact`, `/docs` in both themes, and the script present in the parsed `<head>`) → hiding the flake with a "wait for transitions" helper in the contrast tests, which would have left users seeing the flash. If a dark-theme user ever sees a flash again, check this first.
