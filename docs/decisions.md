## Phase 3 — authentication

- **Auth** → `better-auth` 1.7 with the Prisma adapter, GitHub as the only provider → plan default; its Prisma peer range covers v7. The hand-written `user` / `session` / `account` / `verification` models were diffed against `@better-auth/cli generate` output and match, so no extra migration → Auth.js, Clerk.
- **Scopes** → `read:user user:email` with `disableDefaultScope`; repo access is requested at first export with `linkSocial` (Phase 8) → matches the sign-in copy on the canvas → `repo` at sign-in.
- **OAuth tokens** → `account.encryptOAuthTokens: true` → the GitHub access token is later used server-side for export, so it is encrypted at rest.
- **Session lookups** → `session.cookieCache` (5 min, compact) → fewer DB reads per request; revocation can take up to 5 minutes to apply.
- **Route protection** → `src/proxy.ts` checks only for the session cookie (`getSessionCookie`) on `/`, `/projects`, `/usage`, `/p/*` and redirects to `/sign-in?callbackURL=…`; `requireSession()` and `protectedProcedure` stay authoritative. The proxy does **not** bounce signed-in users away from `/sign-in`: a stale cookie would loop between `/` and `/sign-in`. The sign-in page does that redirect after a real `getSession()`.
- **Open redirects** → `callbackURL` is a nuqs parser (`src/lib/search-params/sign-in.ts`) that only accepts same-origin relative paths; Better Auth also validates it against trusted origins.
- **Welcome credits** → `WELCOME_CREDITS` env var, default 0; a `databaseHooks.user.create.after` writes one `CreditLedger` row (`ADJUSTMENT`, `meta.kind = "welcome"`) only when it is > 0.
- **Spinner inside buttons** → `aria-hidden` on the `Spinner` (it carries `role="status"` + `aria-label="Loading"`), because the button label already says what is happening.
- **Gap (needs pages)** → Terms, Privacy, Docs, Status and Contact links on the sign-in screen are `#` placeholders until those pages exist.
- **E2E signed-in fixture** → `e2e/fixtures/session.ts` inserts a user + session with `@neondatabase/serverless` and sets the HMAC-signed `better-auth.session_token` cookie (same signing as `better-call`); the user row is deleted afterwards.

## Phase 5 — sandbox + coding agent

- **Durable functions** → `inngest` **v4** (4.26) → plan default, latest major; v4 types events with `eventType()`, puts triggers in the function options and ships realtime in core → v3 (still what AgentKit and `@inngest/realtime` were built against).
- **Agent loop** → Vercel **AI SDK** (`ai` v7, already installed for AI Elements types), models through AI Gateway (below), with our own loop in `run-agent`: every model turn and every tool call is its own `step.run`, so retries resume mid-run and each step shows in the Inngest dev server. Tools are declared with `tool({ inputSchema })` and **no `execute`**, so the SDK returns tool calls instead of running them → `@inngest/agent-kit` 0.13.2 (owner's call at Phase 5 start): last stable release Nov 2025 (outside the 6-month rule), built against inngest 3.43, and its OpenAI adapter only speaks Chat Completions, while the AI SDK reaches every provider and reports cached/reasoning token usage.
- **Agent → UI streaming** → Inngest v4 core realtime: `realtime.channel()` (zod topic schemas) + `inngest.realtime.publish()` inside steps, `getClientSubscriptionToken` + `useRealtime` from `inngest/react` for Phase 6 → `@inngest/realtime` 0.4 (depends on inngest v3) and `@inngest/use-agent` 0.4 (last release Oct 2025, AgentKit event set).
- **Publishing** → non-durable `inngest.realtime.publish` called only inside `step.run` callbacks, wrapped so a realtime failure never fails a step → `step.realtime.publish` (one durable step per event: hundreds of steps per run for streamed deltas).
- **Realtime topic names** → single words (`status`, `reasoning`, `text`, `task`, `file`, `tool`, `credits`, `preview`) with a `phase` field where the plan had two events (`file.started` / `file.written`); `text` added for streamed assistant text. Mapping table in `docs/plan.md` §5.3.
- **Token endpoint** → `POST /api/realtime/token` route handler, as the plan's layout lists → tRPC procedure (would also work; kept the plan's file so `useRealtime`'s token factory has a plain URL).
- **Sandbox** → `e2b` 2.63 with the **Template SDK** (`sandbox-templates/nextjs/template.ts`, built by `bun run sandbox:build`) → `@e2b/cli` + Dockerfile (the SDK builds remotely, no Docker or CLI install needed). The template's `shadcn create` and `add --all` steps were checked locally (see the `shadcn create` entry below): the app type-checks and serves 200.
- **Template shadcn style** → `base-nova` on Base UI (`--base base --preset nova`, the same style and Geist font as Vibe's own `b2fA` preset); the system prompt tells the agent to use `render` instead of `asChild` → pinning a Radix style (would differ from Vibe's own components).
- **Sandbox restore** → done in Phase 5 rather than Phase 9: when the stored sandbox is gone, a new one is created and the latest Version's files are written back (plus `npm install` when `package.json` is restored). Without it, every follow-up after the 30-minute timeout would start from an empty template.
- **Version snapshot** → the whole source tree read from the sandbox at the end of a run (not only the files the agent wrote), because Phase 6's Code view and Phase 8's export both read `Version.files`. Lock files, `.env*`, binaries, `node_modules`, `.next`, `.git` are left out; capped at 400 files / 4 MB.
- **Idempotency** → ids derived from the Inngest run id (`run_<runId>_reply|version|debit`) plus `upsert` / existence checks → a new `runId` column (needs a migration and buys nothing over deterministic ids).
- **Metering** → cost-based (owner's call): `ceil(USD cost × CREDITS_PER_USD × CREDIT_MARKUP)`, USD cost from AI Gateway (below). Failed runs are free (owner's call). Pure functions in `src/server/billing/pricing.ts` and `run-cost.ts` → flat per 1K tokens, flat per run, hand-maintained prices in env (the first Phase 5 draft; replaced at the owner's request).
- **Out of credits** → checked before the run (balance ≤ 0: no model call, assistant explains) and after every turn (running cost ≥ balance: stop, keep and charge what was built; the balance can end slightly below 0) → hard stop mid-turn (would lose paid work).
- **Command guard** → small regex denylist (`src/server/sandbox/guards.ts`, unit-tested): `sudo`, dev-server start/stop/build, `kill`, recursive deletes of `/` `~` `.` `*`, `curl | sh`, `.env` → an allowlist (too narrow for a coding agent that needs `npx`, `ls`, `cat`, `tsc`…).

- **Smoke test** → `scripts/agent-smoke.ts` (`bun run agent:smoke`), run with `bun --conditions=react-server` so `server-only` modules import outside Next.js → a Vitest integration test (would need real keys and spend credits on every test run).
- **Model provider** → **Vercel AI Gateway** through the AI SDK (`createGateway` from `ai`; `@ai-sdk/gateway` ships with `ai`) (owner's call: "use AI Gateway, don't stick to OpenAI") → `@ai-sdk/openai` direct (removed): no model catalogue, no pricing, no cost lookup, one provider. The gateway also allows BYOK if the owner wants to bill a provider key directly.

Default `anthropic/claude-sonnet-5.5` via `AI_DEFAULT_MODEL`.
- **Run cost** → **exact** cost per call from `gateway.getGenerationInfo({ id })` (`totalCost`, or `upstreamInferenceCost` for BYOK) using the `generationId` captured with `onLanguageModelCallEnd`, looked up once in a `cost` step at the end of the run (3 tries, 0 / 2 / 5 s, since the record can lag); any call without a result is billed at the live-price estimate. During the run only the estimate is used (live `credits.used`, out-of-credits stop) → estimate only (drifts from the real bill), lookup after every turn (adds latency to every step).
- **Model picker UI** → AI Elements **`model-selector`** (searchable command dialog), adapted to Base UI and our `Command` / `Dialog`; the registry's `ModelSelectorLogo` (an `<img>` from models.dev) is left out → a `Select` (no search) or an own popover. Grouped by provider with price per 1M tokens and an image icon for vision; non-vision models are disabled while images are attached. Loading = skeleton chip, error = "Models unavailable" chip that retries, empty = `CommandEmpty`.
- **Attachment storage** → **Neon Object Storage** (owner's call), private bucket `attachments` declared in `neon.ts` (`@neon/config`, dev dependency), accessed with **`files-sdk`** + its `neon` adapter (MIT, the Neon skill's recommended client; AWS SDK v3 packages as peers) → Vercel Blob, Postgres `bytea`, raw `@aws-sdk/client-s3`. Objects are keyed `users/<userId>/<nanoid>.<ext>`; Postgres stores the key, never the bytes.
- **Upload path** → `POST /api/attachments` route handler (multipart) instead of tRPC, because tRPC's JSON batching doesn't carry files; 4 MB cap per image keeps uploads under Vercel's 4.5 MB request-body limit → presigned browser uploads (would need CORS on the bucket, which Neon's S3 compatibility doesn't document). The client helper lives in `src/lib/upload-attachment.ts`, not in a component.

- **Attachment chips** → `PromptInputAttachment` / `PromptInputAttachments` ported from the AI Elements registry into our `prompt-input.tsx` (they were missing from the installed copy): `HoverCardTrigger` uses `render`, previews use `next/image` with `unoptimized` (blob/data URLs).
- **Database** → migration `agent_models_and_attachments`: `Message.model` and an `Attachment` table (owner, optional message, unique key, name, type, size), additive only.

- **Context size** → `compactHistory()` before every model step: turns older than the last 3 keep their structure, but file contents in old `createOrUpdateFiles` calls become "[N lines written earlier]" and old tool output is cut to 1,500 characters; `readFiles` returns at most 20 k characters per file and 60 k per call → summarising with an extra model call (cost and latency).
- **Model errors** → `classifyModelError()` walks the error, its `cause` and the AI SDK's `lastError`: 429 → Inngest `RetryAfterError` with the gateway's wait (AI Gateway's free tier allows 5 requests per minute per model); 401/403/404 → `NonRetriableError` with a "pick another model" reply (free tier blocks most models); 400/413/422 → `NonRetriableError`; other errors → normal retries → retrying everything (wasted runs and time on errors that can't succeed).
- **Free-tier testing** → only `openai/gpt-5.1-codex-mini`, `moonshotai/kimi-k2.7-code` and `alibaba/qwen3-coder-next` of the curated list were open on the owner's free AI Gateway credits (probed Nov 2026); the local `AI_DEFAULT_MODEL` is set to `openai/gpt-5.1-codex-mini`. With paid credits every curated model works, so the curated list is unchanged.
- **Inngest Dev Server script** → `npm exec --ignore-scripts=false -- inngest-cli@latest dev` → `npx …`, which `bun run` rewrites to `bun x`; Bun skips install scripts, so the CLI binary never downloads.
- **Persist transaction** → `$transaction(fn, { maxWait: 15_000, timeout: 30_000 })` → Prisma's defaults (2 s to start, 5 s to run): over the Neon WebSocket adapter a cold connection took longer than 2 s to open the transaction in the live test, and the snapshot write (up to 4 MB of JSON) needs headroom.

## GitHub export survives a re-login (15 November 2026)

Reported: after signing out and back in, exporting to an existing repository failed with `AUTH_REQUIRED` ("Connect GitHub and allow repository access, then retry the export."), and the dialog's **Retry export** could never succeed.

- **Cause** → Better Auth's sign-in branch (`handleOAuthUserInfo` in `oauth2/link-account.mjs`) replaces `accessToken` but **intentionally leaves `scope` alone** ("Updated only via linkSocial"), and `linkSocial` _merges_ scopes. So the stored `scope` is a high-water mark that never drops, while the token under it is silently downgraded to the sign-in scopes (`read:user`, `user:email`, with `disableDefaultScope`). Every scope gate in the app reads that stale column, so the export passed validation and then died on GitHub's 403.
- **Fix** → `account.updateAccountOnSignIn: false`, so a sign-in no longer overwrites the repo-scoped token obtained at first export → re-requesting `repo` at sign-in (the plan deliberately keeps sign-in minimal, §313) or trusting the stored scope and re-checking the live token on every `github.status` poll (a GitHub request every 2 s while an export runs, for a rate-limited API). GitHub OAuth App tokens do not expire, so nothing is lost by not refreshing them on sign-in; a genuinely dead token is caught by the recovery path below.
- **Recovery** → an `AUTH_REQUIRED` failure clears the account's stored `scope` inside the same transaction that marks the job failed, so `permissions` goes false and the dialog offers **Connect GitHub to retry** instead of a retry that cannot work → leaving the stale scope (the user had no way back: the form only offers `connect()` when the stored scope says no access, so they were stuck retrying forever). Clearing is safe because `linkSocial` merges the scope back on reconnect. Scoped to `failed.count > 0` so a losing duplicate delivery can't clear the scope of the attempt that won.

  - **Model must always be passed.** Leaving it out lets Browserbase's Model Gateway pick a model, which breaks the user-model-only rule. Per-call `model` overrides are never passed either.
  - **(b) Pages:** v4 pages have `evaluate`, `addInitScript` (also on the context), `setViewportSize`, `screenshot` and `url()`.
  - **(c) Sessions:** `StagehandBrowser.sessionId` feeds `sessions.debug`, whose `debuggerFullscreenUrl` is the live view.
- **Structured verdicts without a schema** → Stagehand ships its own zod copy, so a schema from our zod doesn't type-check against `extract` (and could fail at runtime). Interactions run `act`, then a schema-less `extract` that asks for `PASS:` or `FAIL:` plus one sentence, parsed by a tested `parseVerdict` → a cross-instance zod schema.
- **One session per step** → `browse-N` opens, uses and closes the session inside one Inngest step (caps: 120 s of browser time, 8 page loads and 5 interactions, under the route's 300 s maximum), so nothing reconnects across steps → keeping a session open across steps (reconnects, keep-alive billing).
- **Origin lock, two layers** → Browserbase `allowedDomains: [preview host]` restricts top-level navigation, and code builds every URL from the project's preview origin and checks the page origin after every visit and action. A different origin stops the check at once. The model never supplies a URL.
- **Privacy and safety settings** → `recordSession: false` and `blockAds: true`. Page text and errors are redacted, and findings reach the repair model wrapped as untrusted.
- **When it runs** → only when `verify-N` is clean. Browser findings go into the same repair rounds, round caps and rollback as the static checks. Screenshots are attached for vision models through the existing `vibe-attachment:` presigning. A browser that can't run marks the check `skipped` and never fails the run. Stop, the credit balance and the time budget are checked before every browser model call and every step.
- **Live view** → embedded only when the URL passes an allow-list (`https://www.browserbase.com/devtools-fullscreen…`, no credentials, `navbar=false`). The iframe is read-only: `inert`, sandboxed, `pointer-events: none`, `no-referrer`. Disconnect messages are trusted only from the frame's own window, and a reconnect button follows. Composed from existing `Task`, `Badge`, `Skeleton`, `Empty`, `Dialog` and `Spinner`; vibe-ui isn't on this machine, so the owner should review it.
- **Storage and retention** → screenshots go in the existing private bucket under `qa/<projectId>/<runId>/<round>-<viewport>.png`. `message.list` signs them for 1 hour after the ownership check, and project deletion removes them. The nightly cleanup deletes them once they are 30 days old, both from expired messages (their keys are dropped from the part) and by listing `qa/` in paged sweeps, which catches screenshots of failed runs and earlier rounds → a separate bucket, or a bucket lifecycle rule (none is configured on the provider).

## Stop, project names and chat order (owner's report, 18 November 2026)

- **Stop aborts the model call in flight** → `withStopWatch` (`src/inngest/agent/stop-watch.ts`) polls the stop flag every 1.5 s while a model call runs and aborts it with an `AbortSignal` (AI SDK `abortSignal`, checked in the installed types) in the builder/editor/repair turn, the planner, each file writer and the question answer. A stopped call is not billed to the user, because its usage never comes back; the gateway may still bill the partial output → checking the flag only between steps (a run with a slow model kept going for minutes after Stop, and the chat kept saying "Thinking…").
- **The live reply sits under its own prompt** → `liveReplyAnchor` places it after the first pending prompt, so a queued follow-up appears below it, and it reads "Stopping…" once Stop was pressed → always rendering it at the bottom of the chat (it showed up under the newer message and the earlier reply).
- **Project names come from the planner** → the plan has a required `projectName` (one to three words); a first build renames the project once with `cleanProjectName`; the slug never changes. The fallback name (used for the first moments, follow-ups and the builder loop) now stops at the first clause, so "Admin dashboard with a sidebar, stat cards…" becomes "Admin dashboard" → a separate title model call (the harness dropped those on purpose) or the full prompt. Projects created earlier keep their old names; there is no rename control yet.
- **Browser check skip reasons are exact** → a start failure now says why (for example `the browser couldn't start (quota)`, redacted and cut at 160 characters) and is logged, instead of a generic message. With no `BROWSERBASE_API_KEY` the reply says "no Browserbase key is set".
- **Browser adapter order** (found when a skipped check reported "Browser context is unavailable. Attach the browser with await Stagehand.create({ browser })") → `Stagehand.create({ browser })` runs first and only then `browser.context` is used (init script, pages), because the context exists only once Stagehand has attached the browser. A failure after `create` closes Stagehand and then the Browserbase session. `browserbase.test.ts` mocks Stagehand with that same rule, so the real adapter is now covered; the fake provider can't catch it → relying on the fake provider alone, which is how the first version passed every test and still failed on its first real session.
