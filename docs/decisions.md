# Decisions

Package-first log (see `docs/plan.md` §0.1). One line per decision: feature → package → why → rejected alternatives.

## Phase 0 (recorded retroactively)

- **UI primitives** → shadcn/ui `base-nova` style (Base UI, `@base-ui/react`) → set at bootstrap; AI Elements ships a Base UI build → Radix (`new-york`) not used.
- **Class merging** → `cn` (shadcn's compiled clsx + tailwind-merge) → drop-in, smaller → `clsx` + `tailwind-merge`.

## Phase 1 — design system

- **Theme switching** → own `ThemeProvider` (`src/components/theme/`) → `next-themes` 0.4.6 (last release March 2025) fails the "maintained in the last ~6 months" check and renders a `<script>` inside a client component, which React 19.3 reports as an error; ours is ~100 lines with `useSyncExternalStore`, an inline `next/script` `beforeInteractive` init and a `theme-light` root class so `.light` stays free for scoped panels → `next-themes`.
- **URL state** → `nuqs` v2 → plan default; shared parsers in `src/lib/search-params/` → —
- **Icons** → `lucide-react` → plan default; lucide 1.x has no brand marks, so the GitHub mark is a small own SVG (`src/components/icons/github-icon.tsx`) → `react-icons/si` (whole-set dependency for one icon).
- **Toasts** → shadcn `toast` (Base UI Toast) → the shadcn skill prescribes `toast` for Base UI projects; `sonner` is the Radix/Aria choice → `sonner` (the plan named it before the Base UI base was chosen).
- **File-type icons** → `@iconify-json/material-icon-theme` (MIT, dev dependency) + `@iconify/utils`, subset generated by `scripts/generate-file-icons.mjs` into `src/components/files/file-icons.generated.ts` (~7 KB) → matches the canvas (React atom, blue TS square, purple CSS, yellow JSON braces) with no runtime fetch and no 3 MB JSON in the bundle → `@iconify-json/vscode-icons` (renders TSX/JSX as text, doesn't match the canvas), `@iconify/react` online mode (runtime API fetch), hand-drawn SVG map.
- **Code highlighting** → AI Elements `code-block` (Shiki) → plan default. Themes switched to `github-light-default` / `github-dark-default` to match the `--code-*` tokens and pass AA (legacy `github-light` keyword color is below 4.5:1). The `pre` background is transparent so code sits on our surfaces → `shiki` directly.
- **Markdown in chat** → `streamdown` (pulled in by AI Elements) with only the `code` plugin → math (KaTeX), mermaid and CJK plugins removed: heavy and not needed for a coding agent's replies → full plugin set.
- **AI Elements extra deps** → `ai` (types only: `UIMessage`, `ToolUIPart`…), `motion` (Shimmer), `use-stick-to-bottom` (Conversation), `ansi-to-react` (Terminal), `cmdk` (Command), `@radix-ui/react-use-controllable-state` (Reasoning; a tiny state hook, no Radix primitives) → accepted as AI Elements dependencies → —
- **Resizable panes** → shadcn `resizable` (`react-resizable-panels` v4) → plan default → —
- **Contrast testing** → `@axe-core/playwright` (dev only) → the plan requires "axe shows no contrast errors". License is **MPL-2.0**, outside the MIT/Apache/ISC list; accepted as a test-only exception because it is never shipped and every axe package carries the same license → manual contrast checks only.

## AI Elements patches for Base UI

AI Elements was installed from its registry and then adapted. Re-apply these if the components are re-added:

- `prompt-input.tsx`: `DropdownMenuItem` `onSelect` → `onClick`; hover-card delays moved from root to trigger (`delay` / `closeDelay`); `TooltipTrigger` uses `render`.
- `message.tsx`: `TooltipTrigger` uses `render` (it was nesting `<button>` in `<button>`).
- `task.tsx`, `tool.tsx`, `reasoning.tsx`, `web-preview.tsx`: Radix `data-[state=open|closed]` selectors → Base UI `data-panel-open` / `data-open` / `data-closed`.
- `tool.tsx`, `terminal.tsx`, `file-tree.tsx`, `web-preview.tsx`: raw palette colors (`text-green-600`, `bg-zinc-950`…) → tokens (`text-success`, `bg-card`…).
- `code-block.tsx`: render-time ref mutation replaced with keyed state; the synchronous highlight cache is read only after hydration (fixes a hydration mismatch); transparent background; line numbers use `--code-ln`.
- `shimmer.tsx`: `motion.create()` during render replaced with a static `p` / `span` / `div` map.
- `file-tree.tsx`: `aria-selected` / `aria-expanded` on tree items; sans font, matching the Code artboard.

## Token deviations from the canvas (need sign-off)

- Light `--destructive` 0.585 → **0.55** and light `--success` 0.544 → **0.52**: the canvas values give 4.48:1 / 4.47:1 with `--*-foreground` (just under AA).
- Dark `--destructive-foreground`, `--success-foreground` and `--brand-foreground` are **dark** (oklch 0.2): white on the canvas's dark-mode salmon/blue is 2.8:1 / 3.8:1.
- Derived (not on the canvas): `--popover`, `--muted`, `--tab-active`, `--warning`, `--*-foreground`, `--sidebar-*`, `--chart-1…5`, `--code-*`. All are listed on `/design` under "Derived tokens".

## Phase 2 — database, tRPC, env

- **Env validation** → `@t3-oss/env-core` + `zod` in `src/config/env.ts` → typed, fails `dev`/`build` fast (imported from `next.config.ts`), client/server split enforced at runtime; `env-core` (not `env-nextjs`) was the owner's choice, so `runtimeEnv` lists every var explicitly → `@t3-oss/env-nextjs`.
- **ORM** → Prisma **7.10.1**, all Prisma packages pinned → the owner requires v7; `prisma@latest` on npm is now an 8.0 RC, so never install unpinned → Prisma 8, Drizzle.
- **Prisma client** → `prisma-client` generator to `src/generated/prisma` (git-ignored, regenerated by `bun run build` / `bun run db:generate`; no `postinstall`, because `prisma.config.ts` needs `DIRECT_URL` and installs run before env is set) → `@prisma/client` in `node_modules`.
- **Neon driver** → `@prisma/adapter-neon` + `@neondatabase/serverless` → plan default; no `ws` dependency because Node ≥ 22 has a global `WebSocket` (add `ws` only if a runtime lacks it) → `@prisma/adapter-pg` + `pg`.
- **Migrations URL** → `prisma.config.ts` reads `DIRECT_URL` through Prisma's own `env()`, not `src/config/env.ts`, so `migrate deploy` never depends on unrelated app vars.
- **tRPC** → v11 + `@trpc/tanstack-react-query`, `superjson` → plan default. Server prefetch uses `getQueryClient().prefetchQuery(...)` directly (a generic `prefetch` helper failed to type-check against tRPC query options).
- **Dev proof page** → `/dev/trpc` (list + `[slug]`) with skeleton, error, empty and not-found states → proves seed → server fetch → hydrate → client refetch before auth exists; served only when `NODE_ENV !== "production"` or `DEV_ROUTES_ENABLED=true` (Playwright runs a production build, so a pure `NODE_ENV` gate would make the e2e spec impossible). Removed in Phase 4 (with `DEV_ROUTES_ENABLED`) once the real pages and `e2e/projects.spec.ts` covered the same path.
- **Better Auth tables** → hand-written `User`, `Session`, `Account`, `Verification` (table names `user`, `session`, `account`, `verification`) so `Project.userId` has a real FK; Phase 3 re-checks them against `@better-auth/cli generate`.
- **E2E needs data** → specs that use the signed-in fixture are skipped when `DATABASE_URL` is unset.

## Phase 3 — authentication

- **Auth** → `better-auth` 1.7 with the Prisma adapter, GitHub as the only provider → plan default; its Prisma peer range covers v7. The hand-written `user` / `session` / `account` / `verification` models were diffed against `@better-auth/cli generate` output and match, so no extra migration → Auth.js, Clerk.
- **Scopes** → `read:user user:email` with `disableDefaultScope`; repo access is requested at first export with `linkSocial` (Phase 8) → matches the sign-in copy on the canvas → `repo` at sign-in.
- **OAuth tokens** → `account.encryptOAuthTokens: true` → the GitHub access token is later used server-side for export, so it is encrypted at rest.
- **Session lookups** → `session.cookieCache` (5 min, compact) → fewer DB reads per request; revocation can take up to 5 minutes to apply.
- **Route protection** → `src/proxy.ts` checks only for the session cookie (`getSessionCookie`) on `/`, `/projects`, `/usage`, `/p/*` and redirects to `/sign-in?callbackURL=…`; `requireSession()` and `protectedProcedure` stay authoritative. The proxy does **not** bounce signed-in users away from `/sign-in`: a stale cookie would loop between `/` and `/sign-in`. The sign-in page does that redirect after a real `getSession()`.
- **Open redirects** → `callbackURL` is a nuqs parser (`src/lib/search-params/sign-in.ts`) that only accepts same-origin relative paths; Better Auth also validates it against trusted origins.
- **Welcome credits** → `WELCOME_CREDITS` env var, default 0; a `databaseHooks.user.create.after` writes one `CreditLedger` row (`ADJUSTMENT`, `meta.kind = "welcome"`) only when it is > 0.
- **Spinner inside buttons** → `aria-hidden` on the `Spinner` (it carries `role="status"` + `aria-label="Loading"`), because the button label already says what is happening.
- **Gap (needs pages)** → Terms, Privacy, Docs, Status and Contact links on the sign-in screen are `#` placeholders until those pages exist.
- **E2E signed-in fixture** → `e2e/fixtures/session.ts` inserts a user + session with `@neondatabase/serverless` and sets the HMAC-signed `better-auth.session_token` cookie (same signing as `better-call`); the user row is deleted afterwards.

## Phase 4 — app shell, Home, Projects

- **Slug generation** → `@sindresorhus/slugify` 4 (MIT, ESM, typed, released Nov 2026) → transliterates (`&` → `and`, `é` → `e`) so names like "Ember & Oak" give readable slugs; uniqueness comes from the DB: insert, and on a `P2002` on `slug` retry with a 4-character `nanoid` suffix (max 5 tries) → `slugify` (last release ~7 months ago, outside the maintenance window), hand-rolled regex.
- **Project name from the prompt** → own helper (`src/lib/project-name.ts`): first sentence, leading "build me a / an / the…" removed, capped at 48 characters on a word boundary → no package does this; Phase 5 may let the agent rename the project.
- **Relative time** → `Intl.RelativeTimeFormat` with `numeric: "auto"` (`src/lib/relative-time.ts`) → no dependency and gives the canvas copy as-is ("yesterday", "last week", "2 hours ago") → `date-fns` `formatDistanceToNow` ("1 day ago", "7 days ago").
- **⌘K** → shadcn `Command` (`cmdk`, already installed in Phase 1) in `CommandDialog` → plan default → —
- **Projects search** → server-side `contains` / `mode: "insensitive"` on name, slug and description; the URL update uses nuqs `debounce(300)` and the query key a 10-line `useDebouncedValue` (nuqs returns the new state immediately), with `placeholderData: keepPreviousData` so the grid doesn't flash → full-text search (not needed at this size).
- **Limits shared by server and client** → `src/lib/project-limits.ts` (plain module) → a constant exported from a `"use client"` file reaches a Server Component as a client reference, not its value: the layout's prefetch sent `{ limit: <function> }`, failed validation silently (`prefetchQuery` swallows errors) and the page fell back to a client fetch. `e2e/projects.spec.ts` now asserts the server HTML contains the user's projects.
- **Command palette** → this shadcn `CommandDialog` renders `children` straight into `DialogContent`, so callers wrap them in `<Command>` (cmdk crashes with "reading 'subscribe'" otherwise).
- **Not-found status on `/p/[slug]`** → with a `loading.tsx` the response streams, so `notFound()` returns 200 with a `noindex` robots tag rather than a 404 status (documented Next.js behavior); kept, because the skeleton is mandatory.

## Phase 3.1 — public pages

- **Uptime data** → own `HealthCheck` table + `/api/cron/health` probe + Vercel Cron every 5 minutes → no external service needed and the numbers are the app's own; a pure bucketing function (`src/lib/status.ts`) is unit-tested → hosted monitors (Better Stack, UptimeRobot, Instatus: another account and a paid tier for a public status page), faking data (a status page must not).
- **Probe semantics** → the probe runs inside the app and checks the database, so a full outage writes nothing; past hours therefore count missing checks as down, and hours before the first check are "No data". Vercel Hobby limits cron to once a day: the 5-minute schedule needs Pro, or point any external pinger at the same route with the bearer token.
- **Status bars** → plain flex divs coloured with `--success` / `--warning` / `--destructive` / `--muted` + shadcn `Tooltip` → a chart library for 24–168 equal-width bars is overkill and Recharts is reserved for the usage page.
- **Brand marks** → own SVGs for Instagram and LinkedIn (`src/components/icons/`), stroke style like lucide → lucide 1.x has no brand icons, `react-icons` / `simple-icons` would pull in whole sets for two glyphs.
- **Docs content** → typed TS data rendered by one `DocBlocks` component → MDX (`@next/mdx` plus loaders) for six short articles, and a CMS.
- **Legal copy** → drafted from what the app actually stores (Better Auth tables, credit ledger, payments, sandbox providers in the plan); governing law is India because the plan targets Indian billing. Needs the owner's review, it is not legal advice.
